Fingering · research & proposed approach · Sep 2026

Control your computer with your hand, using only a webcam, running entirely on-device.

An open-source, on-device system that turns webcam hand tracking into OS actions: move, click, drag, scroll, zoom and switch desktops. This page covers what already exists, what we measured on this machine, and how we'll build something faster and more reliable than current projects.

Summary

  • This has been done many times, but not done well. GitHub has dozens of "virtual mouse" repos, almost all the same pattern: MediaPipe + OpenCV + PyAutoGUI. Few have calibration, tests, false-trigger protection or low-latency OS injection. That gap is where we can stand out.
  • Tracker: MediaPipe Hand Landmarker (Apache-2.0, cross-platform, 21 landmarks), used behind a pluggable interface so we can add an Apple Vision backend on macOS.
  • Measured on this M1 Pro: 11.9 ms median per frame for one hand. Inference isn't the bottleneck; the camera is. Realistic end-to-end latency from moving your hand to the cursor moving is ≈45–70 ms, about the same as a Bluetooth mouse plus a 30 Hz display.
  • Keep it fast: keep the tracker in VIDEO/tracking mode (never re-detect every frame), capture at 60 fps, smooth with a 1€ filter (not a moving average), and post events directly through native OS APIs (Quartz CGEventPost), not PyAutoGUI, whose default 100 ms pause after every call is fatal.
  • Reliability is what sets us apart: an explicit gesture state machine with hysteresis, clutch/arm gestures, per-user calibration, and a replay test suite of recorded hand sessions that must produce zero actions when you're just talking with your hands.

Mistake #1: raw fingertip as cursor

Pinching moves the index tip, so every click lands a few pixels off. Fix: anchor the cursor to a stable joint (index MCP / palm) and freeze it while a click is being confirmed.

Mistake #2: PyAutoGUI

It sleeps 100 ms after each call by default (PAUSE=0.1), and on macOS it can't send real double-clicks or reliable Spaces shortcuts. Native event APIs avoid both problems.

Mistake #3: always listening

If every hand movement is treated as a command, the system fires whenever you scratch your head. Fix: arm/clutch gestures, pose debouncing, and replay tests that require silence.

4 · Architecture

A one-way pipeline made of pure, testable stages. Only the last stage touches the OS, so everything else can run in tests from recorded sessions with no camera attached.

01

Capture

Webcam frame, mirrored. Newest frame only, never a queue.

~17–33 ms
02

Tracker

HandTracker interface: MediaPipe, or Apple Vision on Mac. Outputs 21 landmarks + handedness.

~12 ms
03

Features

Fingers extended, pinch ratios, palm center, hand scale. Scale-invariant.

<0.1 ms
04

Gesture engine

Pose debounce → state machine (pointer / pinch / drag / scroll / swipe / zoom / paused). Emits Actions.

<0.2 ms
05

Mapping

Calibrated homography from camera space to screen, then the 1€ filter.

<0.1 ms
06

Actuator

Native OS events: Quartz / SendInput / uinput. --dry-run logs only.

<1 ms

Actions are plain data

MoveCursor, Click(button, count), MouseButton(down/up), Scroll, Shortcut("space_right"). New features are new gesture rules that emit these actions, and the OS layer stays untouched. Later, gesture-to-action bindings can live in a user config file, like Gameface does.

Record and replay

A --record flag writes landmarks + timestamps to JSONL. Tests replay the recordings through the engine and check the exact actions produced. "Talking hands" and "reaching past the laptop" recordings must produce zero actions.

6 · Calibration

Explicit: 4-corner calibration (v1)

Point at each screen corner in turn and pinch to confirm. We fit a perspective homography from that comfortable hand region to the full screen, so small, relaxed movements cover the whole display. It's saved per user, and a sensible default box works with no setup.

Implicit: self-correcting (v2)

Borrowed from gestalt: every confirmed click is a labelled data point. A recursive least-squares update with slow forgetting follows posture drift (leaning back, moving the laptop) with no need to recalibrate.

7 · What will make this better than existing projects

speed

≈13 ms of our own latency

Tracking mode, native events, no sleeps, newest-frame-only capture. Frame-time and latency are shown on screen.

trust

Silent when not addressed

Pause fist, hysteresis, debounce, and replay tests in CI that fail if idle hand movement triggers anything.

privacy

100% on-device

No network and no frames stored. Recordings contain landmarks only, never images.

precision

Clicks land where you aim

Stable-joint anchor, cursor frozen during a click, calibrated mapping; later, DynaSpot-style snapping to UI targets using the Accessibility tree.

extensible

Plugin gestures

Gestures are rules that emit plain Action data. Bindings will be configurable, and a learned classifier can be added for custom gestures.

portable

Pluggable backends

Tracker: MediaPipe / Apple Vision. Actuator: macOS / Windows / Linux. The core logic is shared.

9 · Risks and open questions

Arm fatigue ("gorilla arm")

Holding an arm up is tiring. Calibration lets you use small movements with your elbow resting on the desk. Relative/clutch mode is a v2 option.

Lighting and background

Low light increases camera exposure time, which adds latency and jitter. The HUD will warn when FPS drops.

macOS permissions

Needs Camera + Accessibility for the terminal (later, for the app). We check on startup and open the right settings pane.

Dependency pinning

MediaPipe 1.0.x crashes on macOS (verified here). We pin 0.10.21 and track upstream; the tracker interface keeps us from being locked in.
